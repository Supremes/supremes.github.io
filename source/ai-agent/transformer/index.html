从 Token 到推理循环，理解 Transformer

Transformer 不是“会思考的黑盒”，而是一套可重复堆叠的向量变换系统：注意力负责让每个 token 读取上下文，前馈网络负责对每个位置做非线性加工，残差与归一化让深层堆叠保持稳定。LLM 只是把这个结构扩展到海量参数与文本生成目标上。

进入注意力模拟器 查看 Agent 开发启发
Token Embedding 把离散文字映射成连续向量空间。
Self-Attention 每个 token 计算“我该读取谁”。
FFN + Residual 局部加工、保留原信息、稳定深层训练。
LM Head 把最后的隐藏状态投影成下一个 token 概率。
输入 文本被切成 token，并带上位置信息。
变换 多层 block 混合上下文并提炼语义。
输出 逐 token 预测，形成可读文本。
01 / Core judgments

先抓住三个判断，后面的概念会自然落位

如果你是 agent 开发人员，不需要先记公式。先建立结构感：LLM 的能力来自“上下文读取、非线性加工、概率生成”三件事的规模化组合。

Transformer 的核心不是词典，而是上下文路由。

同一个 token 在不同上下文中会读取不同位置的信息。Self-Attention 决定信息从哪些 token 流向当前 token。

LLM 不是一次输出整段答案，而是反复预测下一个 token。

生成时模型每次只给出下一个 token 的概率分布；采样策略、上下文窗口和 KV Cache 决定推理体验。

Agent 能力来自外部循环，不是 Transformer 自带工具执行。

Transformer 产生文本与决策倾向；agent 框架把模型输出接到工具、记忆、检索、计划与执行反馈上。

02 / Concept ladder

由浅入深：把 Transformer 看成一条加工流水线

下面每一层都回答一个问题：输入如何变成向量、向量如何读上下文、上下文如何变成下一步输出。

1

Tokenization：把文本切成模型能处理的离散单元

模型不直接读取“词义”，而读取 token ID。中文、英文、空格、标点、代码片段都可能被切成不同粒度的 token。Prompt 工程的很多边界，例如上下文长度、格式敏感、代码缩进，本质上都受 token 序列影响。

"调用工具解决问题" -> [调用, 工具, 解决, 问题]
2

Embedding：把 token ID 映射成可计算的向量

每个 token 被查表成一个高维向量。向量不是人类可读的定义，而是模型训练后形成的连续坐标：语义、语法、角色、位置和上下文倾向都在后续层中被不断重写。

token_id -> embedding_vector[hidden_size]
3

Self-Attention：每个 token 判断“我应该参考谁”

当前 token 生成 Query，其他 token 生成 Key 和 Value。Query 与 Key 的相似度决定注意力权重；权重再加权汇总 Value，形成新的上下文表示。

softmax(QK^T / sqrt(d)) V
4

Transformer Block：注意力之后还要加工、归一化与保留原信息

一个 block 通常包含 Attention、残差连接、LayerNorm、前馈网络。注意力负责跨 token 混合，FFN 负责每个位置的非线性变换，残差让深层网络不丢失原始信息。

x = x + attention(norm(x)); x = x + ffn(norm(x))
5

Decoder-only LLM：把最后位置的表示变成下一个 token 概率

现代通用 LLM 多是 decoder-only 架构：只能看见当前位置之前的 token。训练时学习“预测下一个 token”，推理时不断把新 token 接回上下文，直到停止条件触发。

hidden_state_last -> logits -> sampled_token
03 / Primary interaction

注意力模拟器：看见 token 如何互相读取

这是本页的核心交互模块。切换步骤、调整注意力温度，观察“当前 token”如何从其他 token 汇总信息。

句子：Agent 调用工具解决问题

当前查询 token 固定为“解决”。矩阵展示它对其他 token 的读取强度。

Q / K / V

同一批 token 会被线性投影成三组向量：Query 用来提问，Key 用来匹配，Value 用来被汇总。

Attention scores

Query 与各个 Key 做相似度计算，再经缩放和 softmax 得到权重分布。

Weighted sum

模型用权重加权汇总 Value，得到当前 token 的上下文表示。

“解决”的读取来源

Token 进入模型

文本先被切成 token，并映射到向量空间。此时每个位置还只是一个局部表示，尚未真正读取上下文。

    04 / Concepts

    关键概念：不要孤立背术语，要看它解决什么问题

    下面的标签页按“注意力、位置、多头、稳定性”组织。每个概念都对应一个架构问题。

    Attention 是动态检索，不是固定规则

    每个 token 都会根据当前上下文重新计算读取权重。因此“工具”在普通句子中可能只是名词，在 agent prompt 中则可能强烈关联函数调用、参数、执行结果。

    Query当前位置发出的“检索请求”。它表达当前 token 需要从上下文里找什么。
    Key每个位置暴露的“可匹配特征”。Query 与 Key 越匹配，注意力越高。
    Value真正被读取并混入当前表示的信息内容。
    Softmax把相似度变成概率式权重；温度越低，分布越尖锐。

    位置编码让模型知道顺序，而不只是集合

    Self-Attention 天生对顺序不敏感。如果不加入位置信息，“用户调用工具”和“工具调用用户”会丢掉关键差异。现代 LLM 常用 RoPE 等相对位置方案，帮助模型处理长距离关系。

    绝对位置给第 1、2、3 个 token 加不同位置向量，简单直接。
    相对位置更关注 token 之间的距离关系，利于泛化到不同长度。
    RoPE通过旋转向量注入相对位置信息，是很多 decoder-only LLM 的常见选择。

    Multi-head 让模型同时看多种关系

    一个 attention head 只能形成一种读取子空间。多头机制让模型并行捕捉语法依赖、指代关系、格式边界、工具调用片段等不同模式，最后再拼接投影回统一隐藏维度。

    Head一套独立的 Q/K/V 投影和注意力分布。
    Concat多个 head 的输出拼接在一起，保留不同视角。
    Output projection把拼接后的多头信息压回模型隐藏维度，供后续层使用。

    残差与归一化是深层堆叠能训练的工程基础

    几十层甚至上百层 Transformer 如果没有稳定结构，很容易梯度不稳定或信息退化。Residual 保留原路径，LayerNorm 控制分布，FFN 提供每个位置的非线性表达能力。

    Residual让 block 学习“增量修改”，而不是每层完全重写。
    LayerNorm稳定每层输入分布，降低训练难度。
    FFN通常是升维、激活、降维，对每个 token 位置独立加工。

    06 / Training vs inference

    训练像批量补全，推理像逐字续写

    理解训练和推理的差异，能解释为什么 KV Cache 重要、为什么长上下文贵、为什么采样参数会改变输出风格。

    训练阶段：并行学习下一个 token

    训练时模型看到大量文本片段，通过 causal mask 保证每个位置只能看过去。一次前向传播可以同时计算多个位置的 next-token loss，因此 Transformer 比 RNN 更适合并行训练。

    loss = cross_entropy(logits[:, t], token[t + 1])

    推理阶段：自回归生成

    推理时模型先读 prompt，预测一个 token；新 token 被追加到上下文，再预测下一个。KV Cache 保存历史 Key/Value，避免每一步重复计算所有历史 token 的投影。

    prompt -> next_token -> append -> next_token ...

    采样参数：控制概率分布如何落地成文字

    Temperature 越高，分布越平，输出更发散；top-p 限制候选集合；贪心解码稳定但可能机械。Agent 场景通常更重视可控性，而不是文学性。

    上下文窗口：不是无限记忆

    模型只能直接读取窗口内 token。长上下文会增加注意力计算与缓存成本；超出窗口的信息需要摘要、检索、外部记忆或任务拆分。

    07 / Agent implications

    Agent 开发人员真正要带走的底层直觉

    理解 Transformer 后，prompt、RAG、工具调用和记忆设计会从“调参玄学”变成“管理上下文与反馈循环”。

    Prompt 是注意力路由设计。

    清晰的角色、目标、约束、输入边界和输出格式，会让模型更容易把注意力放在正确 token 区域。

    RAG 是把外部知识压进上下文窗口。

    检索质量、chunk 粒度、排序、去重和引用格式，会直接影响模型读取哪些 Value。

    Tool calling 是模型文本预测与外部执行器的协议。

    Transformer 只产生调用意图和参数文本；真正执行、重试、权限控制、异常处理在 agent 框架中完成。

    Memory 不是把所有历史都塞回 prompt。

    有效记忆要区分短期任务状态、长期用户偏好、事实知识和可审计事件，并按需要检索注入。

    08 / Misconceptions

    常见误区：知道边界比背公式更重要

    这些误区会直接影响 agent 系统设计质量。

    误区一：Attention 权重就是模型解释
    Attention 权重展示了某层某头的信息路由，但不等于完整因果解释。最终输出经过多层、多头、FFN、残差与非线性组合，不能只看一张 attention heatmap 就断言模型“为什么这么想”。
    误区二：上下文越长越好
    长上下文给模型更多可读信息，也增加干扰、成本和定位难度。Agent 系统更需要信息选择能力：检索、压缩、排序、引用、结构化工作记忆，而不是无差别塞满窗口。
    误区三：幻觉只是模型“不知道”
    幻觉来自 next-token 目标与缺失约束之间的张力。模型会生成看似合理的连续文本。降低幻觉通常需要检索证据、工具校验、输出约束、拒答策略和执行后验证。
    误区四：Agent 失败一定是模型不够强
    很多失败来自上下文污染、工具 schema 模糊、错误反馈不可读、任务拆分不合理、缺少状态机和重试策略。模型只是循环中的一个组件。
    09 / Cognitive loop

    一句话总结 Transformer

    结构上

    Transformer 是 token 表示的堆叠式变换器：Embedding 进入，Attention 混合，FFN 加工，LM Head 输出。

    机制上

    Self-Attention 让每个 token 动态读取上下文，多头让模型同时捕捉多种关系。

    工程上

    Agent 开发的关键是管理上下文、工具反馈和外部状态，而不是期待模型内部自动拥有可靠执行能力。
