AI Agent 的 Tool Registry 该怎么做

四步走：进得来 → 看得懂 → 选得对 → 跑得稳
01进得来
注册与发现
  • 用装饰器 / 注解自动注册，别攒一条 if-else 长链
  • Schema 从函数签名生成，代码是唯一事实源，改一处就够
  • 统一加 namespace 前缀，多个 MCP server 才不会撞名覆盖
适用工具来自多个来源：本地函数、MCP server、远程 API
02看得懂
Schema 设计
  • description 是 prompt 不是文档：写清什么时候用、什么时候别用
  • 参数拍平，少嵌套 object、少 union，模型填不对复杂结构
  • 能枚举就别放自由字符串，把选择题留给模型、填空题留给代码
适用模型总挑错工具、参数老是填错的时候
03选得对
选择与裁剪
  • 工具一多准确率就掉，几十个起就该管，全塞进 context 是白烧 token
  • 按场景分组 + schema 懒加载：先给名字，用到哪个再展开定义
  • 按角色和任务阶段过滤，模型看不见的工具就不会乱调
适用接了一堆 MCP，context 被工具定义吃满的时候
04跑得稳
执行与治理
  • 模型给的参数按外部输入校验，别直接透传进数据库和 shell
  • 超时、重试、幂等 key 一个不能少；写操作必须人工确认
  • 报错要写成模型能照着改的话，别甩 stack trace；结果超长先截断
适用工具开始碰真实数据、准备上生产的时候
Registry 的用户是模型，不是人
判断标准不是「这个工具能不能跑通」，而是「模型能不能在该用它的时候准确选中它」。
写完一个工具先自测：只看 name + description 这两行，我自己选得对吗？
唯一事实源
清晰边界
够用就好
