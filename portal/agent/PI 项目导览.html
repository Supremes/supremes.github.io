01

项目亮点

为什么 pi 值得一读：它不是又一个庞大框架，而是一套设计克制、边界清晰、可被你重塑的 agent 内核。

{ }

小内核，自我扩展

跳过 sub-agent、plan mode 等重特性。你可以让 pi 自己造你要的功能，或装一个第三方 pi package，而非被框架绑架。

≡

双类型分层设计

AgentMessage 与 LLM Message 解耦，仅在调用边界用 convertToLlm 收窄，UI 状态与上下文互不污染。

⟳

双层 Agent 循环

内层处理工具调用与「插话」steering，外层在想停时检查 follow-up——机制与策略彻底分离的钩子式设计。

◍

四种运行模式

interactive 交互 / print(JSON) / RPC 进程集成 / SDK 嵌入。一个内核，覆盖从终端到嵌入式的全场景。

⊟

上下文压缩 & 会话分支

长对话靠 compaction 在 token 上限内续命，会话可分支、可恢复、可迁移——真实产品级的会话工程。

🔒

供应链加固

直接依赖精确锁版本、shrinkwrap 钉死传递依赖、lockfile 提交闸门、--ignore-scripts 安装。把 npm 依赖当作受审代码。

02

四个包，一条依赖链

把鼠标移到任意一个包上 —— 高亮它依赖的全部下游包。lockstep 版本，整体同步发布。

— 顶层 · CLI —
@earendil-works/pi-coding-agent
交互式编码 agent CLI（命令 pi）
— 中层 · 运行时 —
@earendil-works/pi-agent-core
Agent 运行时：工具调用 + 状态管理 + 事件流
— 底层 · 基础设施 —
@earendil-works/pi-ai
统一多 provider LLM API（OpenAI / Anthropic / Google …）
@earendil-works/pi-tui
终端 UI 库：差分渲染，独立无内部依赖

底层稳，顶层薄。pi-ai 与 pi-tui 是零内部依赖的基石；pi-agent-core 在 pi-ai 之上抽象出 agent 循环；pi-coding-agent 把三者组装成可用的 CLI。

想读懂设计，从中层 pi-agent-core 切入最划算——它是「怎么设计一个 agent 循环」的教科书；想看落地工程，再下沉到 pi-coding-agent。

两层循环在做什么？

内层循环INNER不断消费工具结果与用户插话；当 agent 想停下，外层循环OUTER检查是否有 follow-up 消息决定要不要再来一轮。
