# Bitmap：位图与海量判重

## 1. 它是什么

Bitmap 的核心思想是：**用 1 个 bit 表示一个状态。**

如果元素取值范围是 `0 ~ N`，那理论上只需要 `N / 8` 字节就能表达“这个值是否出现过”。

常见定位方式：

- `index = num / 32`
- `offset = num % 32`

## 2. 适合什么场景

- 海量整数判重
- 用户签到 / 活跃位标记
- 黑名单布尔状态
- 稠密 ID 集合统计

一句话：**值域已知、数据稠密、只关心在不在，Bitmap 就很香。**

## 3. 优点

- 空间省
- 判断快，通常是 O(1)
- 去重天然方便

## 4. 局限

- 依赖“值域连续且可预估”
- 不适合超大且稀疏的 key
- 只能表达很有限的状态，通常是 0 / 1

## 5. Bitmap vs Bloom Filter

| 维度 | Bitmap | Bloom Filter |
| --- | --- | --- |
| 是否误判 | 不会误判 | 可能误判存在 |
| 是否要求值域 | 要求较明确 | 不要求连续值域 |
| 适合场景 | 稠密整数集合 | 海量对象快速过滤 |

## 6. 面试怎么答

可以直接说：

1. Bitmap 用 bit 存状态，极省内存。
2. 适合海量整数判重或布尔标记。
3. 问题在于值域太大或太稀疏时不划算。
4. 如果是对象集合过滤，一般会联想到 Bloom Filter。
