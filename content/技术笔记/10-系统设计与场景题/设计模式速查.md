# 设计模式速查

> 面试不要只背定义，优先回答“它解决什么问题、Spring 里落在哪、业务里怎么用”。

| 模式 | 解决什么问题 | Spring / Java 常见落点 | 面试一句话 |
| --- | --- | --- | --- |
| 单例 | 统一生命周期、减少重复创建 | Spring 默认 `singleton` Bean | 常见，但单例不等于线程安全 |
| 工厂 | 隐藏对象创建细节 | `BeanFactory`、`ApplicationContext`、`@Bean`、`FactoryBean` | 调用方只关心“拿对象”，不关心“怎么 new” |
| 策略 | 运行时替换规则 / 算法 | `PasswordEncoder`、`HttpMessageConverter`、支付渠道分发 | 用接口 + 多实现替代 if/else |
| 代理 | 不改原代码前提下做增强 | AOP、`@Transactional`、`@Cacheable`、`@Async` | Spring 的事务和缓存本质大量靠代理 |
| 模板方法 | 固定流程，开放局部扩展点 | `JdbcTemplate`、`RedisTemplate`、`TransactionTemplate` | 框架把重复样板藏起来，业务只填空 |
| 责任链 | 多步骤串联处理 | Filter、`HandlerInterceptor`、Spring Security Filter Chain | 每一环只管自己那一段 |
| 观察者 | 发布者和订阅者解耦 | `ApplicationEventPublisher`、`@EventListener` | 适合发消息、审计、异步通知 |
| 适配器 | 让不兼容接口协同工作 | `HandlerAdapter` | 旧接口不用改，包一层就能接入 |
| 外观 | 给复杂子系统一个统一入口 | `JdbcTemplate`、`RestTemplate` | 对外简单，对内复杂 |

## 高频追问

### 1. Spring 最常被问到的模式

- 工厂
- 单例
- 代理
- 模板方法
- 责任链

### 2. 代理模式为什么高频

因为 Spring 很多“看起来像注解”的能力，本质都依赖代理增强：

- 事务
- 缓存
- 异步
- 参数校验

### 3. 策略模式在业务里怎么落

最典型就是：

- 支付渠道分发
- 营销规则分发
- 风控规则分发
- 导出格式分发

不要再写一大串 `if-else` 去分支。
