# 集合框架高频考点

> 面试答集合，先回答“怎么选”，再回答“底层为什么”。

## 一句话选型

| 场景 | 首选 | 你要说出来的理由 |
| --- | --- | --- |
| 顺序、可重复、随机访问多 | `ArrayList` | 连续内存，查询快，遍历友好 |
| 头尾入队/出队 | `ArrayDeque` | 比 `LinkedList` 更轻量，缓存友好 |
| 唯一去重，不关心顺序 | `HashSet` | 本质是 `HashMap` 的 key 集合 |
| 唯一去重，还要保留插入顺序 | `LinkedHashSet` | 哈希表 + 双向链表 |
| 唯一去重，还要排序 | `TreeSet` | 红黑树，按比较器排序 |
| 默认键值存储 | `HashMap` | 平均 `O(1)`，工程默认选型 |
| 既要键值，又要顺序/LRU | `LinkedHashMap` | 插入顺序 / 访问顺序可控 |
| 多线程共享 Map | `ConcurrentHashMap` | JDK 8 以后是 CAS + `synchronized` |

## 30 秒总述

- `List` 关注**顺序和重复**；后端默认先想 `ArrayList`。
- `Set` 关注**唯一性**；默认 `HashSet`，要顺序用 `LinkedHashSet`，要排序用 `TreeSet`。
- `Map` 关注**按 key 检索**；默认 `HashMap`，并发场景用 `ConcurrentHashMap`，缓存/LRU 场景看 `LinkedHashMap`。

## ArrayList

### 一句话结论

底层是动态数组，**查得快、尾插便宜、中间插删贵**。

### 30 秒口述

`ArrayList` 底层是连续数组，所以按下标访问是 `O(1)`；尾部追加通常也是 `O(1)` 均摊，但容量不够时会扩容并拷贝。中间插入、删除要搬移元素，所以是 `O(n)`。它不是线程安全的，多线程读多写少可以考虑 `CopyOnWriteArrayList`。

### 关键追问 / 坑

- 扩容不是每次都扩，JDK 里通常按 **1.5 倍**增长。
- `remove(index)` 会触发数组搬移，别只背“删除快”。
- `subList()` 是**视图**不是独立副本，原列表结构变化可能连带出问题。

## LinkedList

### 一句话结论

底层是双向链表，**只有“已拿到节点”时插删才真便宜**。

### 30 秒口述

`LinkedList` 适合从两端增删，因为头尾操作不需要整体搬移；但随机访问必须沿链表走，复杂度是 `O(n)`。很多人背“插入删除快”，这句话不完整：如果你先要找位置，找位置本身就已经是 `O(n)` 了。工程里把它当队列时，通常 `ArrayDeque` 更常用。

### 关键追问 / 坑

- 不要把 `LinkedList` 说成“全面优于 `ArrayList`”；后端大多数场景正相反。
- `LinkedList` 每个节点都是独立对象，**内存占用更高**，CPU 缓存友好度更差。
- 真要双端队列，优先比较 `ArrayDeque`。

## HashMap

### 一句话结论

`HashMap` 是 Java 后端最常用的 Map，底层是**数组 + 链表 / 红黑树**。

### 30 秒口述

`HashMap` 先对 key 求 hash，再定位到桶；桶里元素少时走链表，冲突严重时会树化成红黑树。平均复杂度是 `O(1)`，但前提是 hash 分布足够均匀。它允许一个 `null` key 和多个 `null` 值，但**不是线程安全**的。

### 关键追问 / 坑

- 默认负载因子是 **0.75**，空间和冲突率的折中。
- 树化阈值通常记 **8**，退化回链表阈值 **6**，而且数组容量要先达到 **64** 才会树化。
- 把**可变对象**当 key 很危险：`equals()` / `hashCode()` 变了就再也找不回来了。
- 并发写 `HashMap` 不安全，JDK 7 扩容时期甚至可能出现链表死循环问题。

## ConcurrentHashMap

### 一句话结论

并发场景下默认用它；JDK 8 以后核心思路是**CAS + 桶级同步**，而不是早期的 Segment 分段锁。

### 30 秒口述

`ConcurrentHashMap` 的读路径尽量无锁，写冲突时只锁住当前桶，吞吐量比整表大锁更好。它不允许 `null` key / `null` 值，因为并发语义下无法区分“key 不存在”还是“value 就是 null”。复合操作不能自己先 `get` 再 `put`，要优先用 `putIfAbsent`、`computeIfAbsent`、`merge` 这种原子 API。

### 关键追问 / 坑

- 面试一定要说：**JDK 8 以后不再是 Segment**。
- `computeIfAbsent()` 的 mapping 函数不要写重逻辑或副作用代码，容易放大锁竞争。
- “线程安全”不等于“所有业务组合操作都安全”，先查后改仍然可能有竞态。

## 常见追问速记

- `ArrayList` vs `LinkedList`：后端默认先选 `ArrayList`，别被“链表插删快”误导。
- `HashMap` vs `Hashtable`：`Hashtable` 是历史产物，方法级同步，性能和设计都更旧。
- `HashMap` vs `ConcurrentHashMap`：一个单线程默认选型，一个并发默认选型。
- fail-fast 是什么：遍历时检测到结构性修改就尽快抛 `ConcurrentModificationException`，是**尽力而为**，不是并发安全保证。
- 读多写少的线程安全 List：`CopyOnWriteArrayList`，代价是写时复制，别拿来高频写。

## 面试 Checklist

- 能先按 `List / Set / Map` 说清选型。
- 能解释 `ArrayList` 扩容和 `LinkedList` 的真实复杂度。
- 能讲清 `HashMap` 的桶、冲突、树化、负载因子。
- 能讲清 `ConcurrentHashMap` 为什么不能存 `null`，以及为什么推荐原子复合 API。
