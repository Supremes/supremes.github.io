# 操作系统 P0 主线

> 操作系统面试常围绕三件事：**CPU 怎么调度、内存怎么隔离、I/O 怎么高效完成。**

## 1. 进程与线程

| 维度 | 进程 | 线程 |
| --- | --- | --- |
| 资源 | 资源分配基本单位 | CPU 调度基本单位 |
| 地址空间 | 通常独立 | 同进程线程共享地址空间 |
| 切换成本 | 更高 | 相对更低 |
| 隔离性 | 更强 | 更弱 |

一句话：**进程像独立房间，线程像房间里的多个工人。**

## 2. 用户态与内核态

- **用户态**：应用程序运行的大部分时间
- **内核态**：操作系统核心代码运行，权限更高

什么时候会切到内核态：

- 系统调用
- 中断
- 异常（如缺页）

面试高频点：**用户态 / 内核态切换有成本，所以很多性能优化都在减少切换次数。**

## 3. 虚拟内存与分页

### 虚拟内存

虚拟内存不是“凭空多出内存”，而是给每个进程提供一套**连续、隔离、统一**的地址空间。

好处：

- 进程隔离
- 简化编程模型
- 支持按需加载
- 让物理内存与磁盘交换成为可能

### 分页

- 虚拟地址按页切分
- 通过页表映射到物理页
- TLB 用来缓存热点地址映射
- 缺页时触发 page fault，再由 OS 补齐映射

## 4. 上下文切换

上下文切换要保存和恢复：

- 寄存器
- 程序计数器
- 栈信息
- 调度相关状态

为什么贵：

- 不是纯 CPU 计算
- 可能引起 cache / TLB 失效
- 线程越多不一定越快

## 5. 同步与互斥

常见手段：

- mutex
- rwlock
- semaphore
- condition variable
- CAS / 原子类

最短理解：

- **互斥**：同一时刻只能一个人改
- **同步**：控制先后顺序和协作关系

## 6. 阻塞 / 非阻塞

不要混淆两个维度：

- **阻塞 / 非阻塞**：线程调用后要不要等
- **同步 / 异步**：结果是不是由当前线程自己拿回来

例如：

- 阻塞 I/O：调用线程一直等
- 非阻塞 I/O：立即返回，数据没到就再试

## 7. select / poll / epoll

| 机制 | 特点 | 局限 |
| --- | --- | --- |
| select | 最早、通用 | fd 数量有限，遍历成本高 |
| poll | 去掉了 select 的位图限制 | 仍然需要线性遍历 |
| epoll | 事件驱动，fd 多时更合适 | 只在 Linux 可用 |

一句话：

- select / poll 是“**我每次都问一遍谁好了**”
- epoll 是“**谁好了谁通知我**”

## 8. 零拷贝

零拷贝不是真的“完全没有拷贝”，而是**减少用户态和内核态之间的数据拷贝与切换**。

常见收益：

- CPU 更省
- 吞吐更高
- 上下文切换更少

常见实现：

- `sendfile`
- `mmap + write`

典型场景：文件下载、静态资源分发、网关转发。

## 9. 复习时的最短串法

1. 进程 / 线程回答调度和隔离。
2. 用户态 / 内核态、虚拟内存、分页回答内存和权限。
3. 阻塞 / 非阻塞、select / poll / epoll、零拷贝回答高性能 I/O。
