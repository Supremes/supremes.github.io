# 计算机网络 P0 主线

> 主线就一条：**数据怎么可靠地发出去，怎么高效地传，怎么安全地传，最后怎么通过代理和负载均衡扩起来。**

## 1. TCP：建连、断连、可靠性

### 三次握手

目的不是“打招呼三次”，而是**双方都确认收发能力正常，并同步初始序列号**。

最短回答：

1. Client 发 SYN，告诉服务端“我要连，你看我的起始序列号是这个”。
2. Server 回 SYN + ACK，表示“我收到了，我也给你我的起始序列号”。
3. Client 再回 ACK，表示“你的我也收到了”，连接建立。

### 四次挥手

因为 TCP 是**全双工**，两边都要各自关闭发送通道，所以通常是四次。

### 可靠性怎么保证

- 序列号
- ACK 确认
- 超时重传
- 滑动窗口 / 流量控制
- 拥塞控制
- 校验和

### 高频追问

- **TIME_WAIT**：主动关闭方等待一段时间，确保最后 ACK 能重传，也避免旧连接报文污染新连接。
- **CLOSE_WAIT**：被动关闭方收到了 FIN，但应用还没把自己的连接关掉；太多通常说明程序没及时 close。

## 2. HTTP 版本差异

| 版本 | 核心变化 | 记忆点 |
| --- | --- | --- |
| HTTP/1.0 | 默认短连接 | 每次请求基本都重新建连 |
| HTTP/1.1 | Keep-Alive、管线化、Host | 解决了大部分复用问题，但仍有队头阻塞 |
| HTTP/2 | 二进制分帧、多路复用、Header 压缩 | 同一连接并发多个请求，常见于 HTTPS |
| HTTP/3 | 基于 QUIC（UDP） | 解决 TCP 层队头阻塞，弱网体验更好 |

一句话：**HTTP/2 解决应用层复用问题，HTTP/3 连传输层也一起换了。**

## 3. HTTPS / TLS

HTTPS = **HTTP + TLS**。

TLS 握手的核心目标：

1. 验证服务端身份
2. 协商加密套件
3. 安全地产生会话密钥
4. 后续数据走对称加密，提高性能

你可以这样答：

- 证书负责证明“你连的是谁”
- TLS 握手负责解决“密钥怎么安全协商出来”
- 真正传大流量时，通常还是用对称加密

## 4. DNS

DNS 本质上是：**把域名翻译成 IP，并且尽量复用缓存。**

常见链路：

1. 浏览器缓存
2. 操作系统缓存
3. 本地域名服务器
4. 根域名服务器
5. 顶级域名服务器
6. 权威域名服务器

高频点：

- **TTL** 决定缓存多久
- **CNAME** 常用于接 CDN、流量调度
- DNS 查询结果不一定唯一，常结合就近接入和负载均衡

## 5. 长连接

“长连接”面试里经常混着说，最好拆开：

- **TCP 长连接**：连接不立刻断，后续请求复用
- **HTTP Keep-Alive**：HTTP/1.1 默认倾向复用 TCP 连接
- **HTTP/2 多路复用**：一个连接里并发多个流
- **WebSocket**：建立后双向通信，适合实时推送

## 6. 代理与负载均衡

### 正向代理 vs 反向代理

| 维度 | 正向代理 | 反向代理 |
| --- | --- | --- |
| 代理对象 | 客户端 | 服务端 |
| 目的 | 隐藏客户端、突破访问限制 | 隐藏服务端、统一入口 |
| 客户端是否感知 | 感知，需要配置代理 | 通常无感知 |
| 常见用途 | 公司出口代理、科学上网 | Nginx、网关、CDN |

### 负载均衡

负载均衡常借助反向代理来做。

- **L4**：按 IP/端口转发，性能高
- **L7**：按 URL、Header、Cookie 转发，策略更灵活

常见算法：

- 轮询
- 加权轮询
- 最少连接
- 一致性哈希

## 7. 复习时的最短串法

1. TCP 保证连接和可靠传输。
2. HTTP 定义应用层请求响应。
3. HTTPS 用 TLS 解决身份和加密。
4. DNS 帮你找到目标 IP。
5. 代理、长连接、多路复用、负载均衡解决性能与扩展性。
