## 一、大模型开发全流程地图

可以拆成 6 个阶段，前后串成一条流水线：

```
1. 数据工程  →  2. 预训练  →  3. 后训练  →  4. 评估  →  5. 部署/推理  →  6. 监控与迭代
   (Data)       (Pretrain)    (Post-train)   (Eval)      (Serving)        (Ops/Flywheel)
```

|阶段|核心目标|产出物|
|---|---|---|
|数据工程|收集、清洗、去重、配比语料|高质量 token 数据集|
|预训练|让模型学会"世界知识 + 语言能力"|Base Model（基座）|
|后训练|让模型"听话、有用、安全"|Instruct/Chat Model|
|评估|量化能力与风险|Benchmark 分数 + 红队报告|
|部署|高效、低成本地提供服务|推理服务/API|
|监控迭代|收集反馈持续改进|数据飞轮|

这里**预训练决定能力上限，后训练决定能力的可用性**，二者是重点，下面分别展开。

---

## 二、预训练（Pre-training）—— 打地基

### 1. 本质

用海量无标注文本，做**自监督学习**：让模型预测"下一个 token"（Next Token Prediction）。模型在不断预测的过程中，被迫把语法、事实、推理模式压缩进参数里。

目标函数（自回归语言建模）：

$$ \mathcal{L} = -\sum_{t} \log P(x_t \mid x_{<t};\ \theta) $$

即最大化在给定前文的条件下，真实下一个 token 的概率。

### 2. 数据（重要性常被低估）

- **来源**：网页（CommonCrawl）、代码（GitHub）、书籍、论文、百科、问答社区等。
- **关键处理**：
    - **质量过滤**：用规则 + 分类器剔除垃圾/广告/乱码。
    - **去重（dedup）**：跨文档去重极其重要，重复数据会让模型"死记硬背"、浪费算力。
    - **数据配比（data mixture）**：代码、中英文、知识类的比例直接影响模型性格。比如想要强推理，就提高代码和数学占比。
    - **课程学习（curriculum）**：有些做法是后期提高高质量数据比例。
- **规模**：现代模型动辄 **数万亿 token（trillions）**。

### 3. 模型结构

主流是 **Decoder-only Transformer**，关键组件：

- **Attention**：捕捉长距离依赖；工程上用 Flash Attention 降显存、提速。
- **位置编码**：RoPE（旋转位置编码）成为事实标准，便于外推长上下文。
- **归一化/激活**：RMSNorm + SwiGLU 是当前常见组合。
- **MoE（混合专家）**：用稀疏激活在"参数量大但推理算力可控"之间取平衡（如 Mixtral、DeepSeek）。

### 4. Scaling Law（缩放定律）

模型能力随**参数量 N、数据量 D、算力 C**呈幂律提升。Chinchilla 的关键结论：**给定算力，参数和数据要按比例一起涨**（大约每个参数配 ~20 token），而不是一味堆参数。这直接指导"该训多大模型、喂多少数据"。

### 5. 工程挑战（这是真正的硬骨头）

- **分布式并行**：数据并行（DP）、张量并行（TP）、流水线并行（PP）、序列并行、ZeRO/FSDP 显存切分，组合使用。
- **稳定性**：大规模训练常遇 loss 突刺（spike）、梯度爆炸、硬件故障，需要 checkpoint、自动续训。
- **成本**：一次大模型预训练耗资数百万美元、数千张 GPU 训练数周。

> 预训练的产出叫 **Base Model**：知识渊博，但"不听话"——你问它问题，它可能继续补全你的问题而不是回答，因为它只学会了"续写"，没学会"对话"。

## 三、后训练（Post-training）—— 把基座调教成"助手"

后训练是把"会续写的语言模型"变成"有用、诚实、无害（Helpful, Honest, Harmless）的助手"。通常分三步：

### 第 1 步：SFT（监督微调，Supervised Fine-Tuning）

- **做法**：用人工或高质量的「指令-回答」对（instruction-response pairs）继续训练，目标函数和预训练一样（预测下一个 token），但数据变成了**对话格式**。
- **作用**：教会模型"看到指令要回答"、模仿优质回答的风格和格式。
- **关键**：数据**质量 > 数量**。少量高质量数据（如 LIMA 的思路）就能激发出基座里已有的能力——这印证了"能力在预训练阶段就具备了，SFT 只是对齐表达方式"。

### 第 2 步：偏好对齐（Preference Alignment）—— 后训练的精华

SFT 只能模仿"标准答案"，但很多时候"什么是好回答"很难写出唯一标准，却**容易比较两个回答谁更好**。于是引入基于人类偏好的训练：

#### (a) RLHF（基于人类反馈的强化学习）—— 经典三步

1. **收集偏好数据**：对同一问题生成多个回答，人工标注排序（A 比 B 好）。
2. **训练奖励模型（Reward Model, RM）**：学习给回答打分，拟合人类偏好。
3. **强化学习优化（PPO）**：用 RM 当"裁判"，让语言模型生成能拿高分的回答；同时加 **KL 惩罚**，防止模型为了讨好奖励而偏离原始分布太远（即防止 reward hacking）。

$$ \max_{\theta}\ \mathbb{E}\big[r_\phi(x,y)\big] - \beta,\mathrm{KL}\big(\pi_\theta ,|, \pi_{\text{ref}}\big) $$

#### (b) DPO（直接偏好优化）—— 更简单的新主流

PPO 流程复杂、训练不稳。**DPO** 把"训奖励模型 + 强化学习"两步合并，直接用偏好数据对语言模型做一个分类式的优化，无需显式奖励模型和在线采样。**工程上更稳、更省，已成为很多团队的首选**。此外还有 GRPO（DeepSeek 用于推理）、KTO、ORPO 等变体。

#### (c) RLAIF / Constitutional AI

用 **AI 代替人类**来产生偏好标注（Anthropic 的"宪法 AI"），用一套原则让模型自我批评、自我改进，降低对人工标注的依赖。

### 第 3 步：面向能力的强化（推理时代的新重点）

近一两年的关键进展：用 **可验证奖励的强化学习（RLVR）** 提升**推理能力**。

- 在数学、代码这类**答案可自动验证**的任务上，对就给正分、错就给负分。
- 模型通过 RL 自发学会**长链思考（Chain-of-Thought）、自我反思、回溯**，催生了 o1、DeepSeek-R1 这类"推理模型"。
- DeepSeek-R1 还证明了：纯 RL（GRPO）甚至能在很少 SFT 的情况下涌现出强推理能力。

## 四、预训练 vs 后训练对比小结

|维度|预训练|后训练|
|---|---|---|
|目标|学知识、学语言（能力上限）|对齐意图、变得可用安全|
|数据|海量无标注文本（万亿 token）|少量高质量指令/偏好数据|
|方法|自监督，预测下一 token|SFT + 偏好对齐 (RLHF/DPO) + RL|
|算力|极大（数周、数千卡、数百万美元）|相对小（但 RL 也不便宜）|
|产出|Base Model（会续写）|Chat/Instruct/Reasoning Model（会对话、会推理）|
|一句话|决定模型"懂多少"|决定模型"好不好用"|

**核心直觉**：预训练把知识"压"进参数里，后训练把这些知识"对齐"到人类想要的表达和行为上。能力的天花板在预训练就定了，后训练是在天花板下把能力释放、规整出来。

---

## 五、其余环节（简要补充）

- **评估**：通用 benchmark（MMLU、GSM8K、HumanEval 等）+ 人类偏好竞技场（Chatbot Arena）+ 安全红队（red-teaming）。注意防"刷榜"和数据污染。
- **部署/推理优化**：量化（INT8/INT4）、KV Cache、PagedAttention（vLLM）、投机解码（speculative decoding）、蒸馏出小模型。
- **数据飞轮**：上线后收集真实用户反馈 → 清洗成新的训练数据 → 回流到后训练，形成持续迭代闭环。
