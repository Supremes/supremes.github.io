# Agent 模型路由与多模态

模型路由根据任务能力、风险、延迟和成本选择模型。多模态路由还要处理消息格式、附件生命周期和能力升级。

## 复习范围

| 主题 | 要讲清的内容 |
|---|---|
| 静态路由 | 按任务类型固定模型 |
| 动态路由 | 分类器或强模型判断复杂度 |
| Capability Routing | 文本、视觉、音频、工具能力匹配 |
| Escalation | 轻模型失败后升级，保留状态和证据 |
| Fallback | 限流、超时、区域故障时降级 |
| 选型评测 | 质量、延迟、成本、稳定性联合比较 |

## 高频问题

1. 为什么不能按 Prompt 长度简单判断任务难度？
2. 第一轮是文本、第二轮出现图片，怎么无感切换模型？
3. 路由器选错模型后如何恢复？
4. 多模型 fallback 如何保持输出和工具协议一致？
5. 轻模型节省的成本，会不会被失败重试吃掉？
6. 如何避免路由本身成为高延迟单点？

## 设计约束

- 为模型维护能力矩阵和固定版本。
- 路由决策写入 Trace，支持离线复盘。
- 升级模型时传递原始证据，不只传摘要。
- 失败切换前判断工具是否已经产生副作用。
- 比较 `cost_per_success`，不要只比较 token 单价。

## 失败模式

- 把复杂任务误分给轻模型。
- 模型切换后不支持原工具 Schema。
- 多模态附件在重放或持久化时丢失。
- fallback 反复切换，形成隐性循环。
- 新模型公开榜单更高，但核心任务桶退化。

## 项目证据

准备一张模型能力矩阵和一组路由混淆样本。说明路由前后成功率、p95 延迟和成功任务成本。
