# Agent Multi-Agent 协作

Multi-Agent 用多个角色分担上下文和职责。只有任务可以并行、专业能力确实不同或上下文需要隔离时，它才比单 Agent 更划算。

## 复习范围

| 模式 | 特点 |
|---|---|
| Agent as Tool | 主 Agent 保持控制，子 Agent 返回结果 |
| Handoff | 控制权转给另一个 Agent |
| Supervisor | 中央角色分配、检查和汇总 |
| Peer-to-Peer | 角色直接通信，协调成本高 |
| Parallel Workers | 独立任务并行，最后聚合 |

## 高频问题

1. 什么时候该拆子 Agent，什么时候不该拆？
2. Agent as Tool 和 handoff 有什么区别？
3. 子 Agent 应继承多少父上下文？
4. 多 Agent 如何共享文件、状态和消息？
5. 两个 Agent 同时修改同一资源怎么处理？
6. 如何评测协作质量，而不只看最终答案？

## 设计约束

- 给每个 Agent 明确输入、输出和权限。
- 委派任务要有可验证的完成条件。
- 并行任务必须真正独立。
- 汇总者要拿到原始证据，不只拿摘要。
- 限制层级、消息轮数、总 token 和重复委派。

## 失败模式

- 多个 Agent 重复调查同一问题。
- 摘要丢失限定条件，错误逐层放大。
- 所有角色使用相同能力和上下文，只增加成本。
- 并发写文件造成覆盖或冲突。
- Supervisor 成为新的单点瓶颈。
