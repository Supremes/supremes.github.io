# Agent 系统设计与行为面试

系统设计题考察边界和取舍。行为题考察你是否真的做过。两类题都不接受只报框架名或产品名。

## 系统设计答题顺序

1. 明确用户、任务、成功标准和失败成本。
2. 画输入、Context、模型、工具、状态和输出。
3. 找出副作用、权限和不可控外部依赖。
4. 设计超时、取消、重试、幂等和恢复。
5. 定义 Trace、指标、评测集和发布门槛。
6. 讨论规模、成本、延迟和降级。

## 高频系统设计题

- 设计一个客服 Agent。
- 设计一个 Coding Agent。
- 设计 Deep Research Agent。
- 设计 1000 个工具的发现与调用系统。
- 设计带长期记忆的个人助手。
- 设计多 Agent 代码审查系统。
- 设计 Agent 评测平台。
- 设计远端 Sandbox 执行系统。

## 行为面试准备

至少准备四类项目：

| 案例 | 面试官关注 |
|---|---|
| 修复线上失败 | 定位证据、根因、恢复和防复发 |
| 架构取舍 | 为什么没选另一方案 |
| 指标冲突 | 质量、成本、延迟如何平衡 |
| 推动落地 | 如何让团队接受规范或平台 |

STAR 中的 Action 要写你做了什么，不要只说“团队完成了”。Result 使用真实数字。没有数字时，写可验证的交付物和影响范围。

## 常见追问

1. 这个设计最脆弱的地方是什么？
2. 流量扩大 10 倍后先坏哪里？
3. 模型换代后哪些组件可以删除？
4. 评测分数和业务反馈冲突怎么办？
5. 你做错过什么判断，后来怎么发现？
6. 如果重新做一次，会先改什么？

## 项目材料清单

- 一张架构图。
- 一条成功 Trace 和一条失败 Trace。
- 一份版本对比数据。
- 一次故障或错误决策复盘。
- 一项明确没有做的功能，以及不做的理由。
