# Agent 安全与权限

Agent 会读取不可信内容，也会调用真实工具。安全设计要把模型当成可能受诱导的决策者，权限和副作用由确定性系统控制。

## 复习范围

| 边界 | 控制 |
|---|---|
| 输入 | Prompt Injection、附件、网页和工具输出 |
| 身份 | 用户、Agent、服务和工具凭证 |
| 授权 | actor、resource、action、context |
| 执行 | sandbox、网络、文件、进程和资源限制 |
| 数据 | secret、PII、日志脱敏、保留策略 |
| 输出 | 数据外泄、危险内容、对外发送确认 |

## 高频问题

1. Prompt Injection 为什么不能只靠 System Prompt 防？
2. 模型能看到工具，不代表它有权限调用。工程上怎么分离？
3. 用户授权和工具服务凭证如何传递？
4. 长时间运行的 Agent 如何处理 token 过期？
5. 工具输出再次进入模型前要做什么？
6. 什么操作必须 Human-in-the-Loop？

## 防线

- 不可信内容与系统指令分区。
- 工具调用前做参数和权限检查。
- 最小权限、短期凭证、按任务注入。
- 写操作按风险分级，必要时确认。
- 沙盒限制文件、网络、进程和资源。
- Trace 默认不记录 secret 和完整敏感内容。

## 失败模式

- 把 API key 放进 Prompt。
- 只在会话开始鉴权，后续工具调用直接放行。
- 让模型自己判断是否有权限。
- 工具结果中的恶意文本覆盖系统意图。
- 日志和评测数据泄露用户内容。
