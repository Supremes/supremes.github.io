# Agent Context 与 Memory

Context 是当前调用送进模型的工作集。Memory 是跨 turn 或跨 session 保留、检索和更新的信息。两者不能混为一谈。

## 复习范围

| 层次 | 内容 |
|---|---|
| Working Context | system、tools、history、retrieval、current input |
| Short-term State | 当前任务计划、临时变量、未完成工具调用 |
| Long-term Memory | 用户事实、偏好、历史事件、经验规则 |
| Memory Pipeline | 提取、规范化、去重、写入、检索、遗忘 |
| Context Engineering | Select、Compress、Isolate、Write |
| 质量指标 | 命中率、精确率、时效性、冲突率、作用域正确率 |

## 高频问题

1. Memory 与 RAG 有什么区别？
2. 为什么不能把所有历史对话都塞进 Context？
3. 用户新要求与旧偏好冲突时，谁优先？
4. 如何处理过期、重复和互相矛盾的记忆？
5. 什么时候写 Memory，谁来验证提取结果？
6. 如何评测“检索到了，但用错了作用域”？

## 建议的数据模型

每条长期记忆至少记录：

- `subject`、`predicate`、`value`
- 来源和证据
- 作用域
- 生效时间与过期时间
- 置信度
- 版本和冲突关系

## 失败模式

- 把推测写成事实。
- 旧偏好覆盖当前明确指令。
- 检索命中，但人物或时间关系拼错。
- 压缩时丢失否定词、数字和约束。
- 不做遗忘，Context 被低价值记忆占满。

## 项目证据

准备一个记忆冲突案例。展示原始对话、提取结果、检索结果、最终决策和修复后的回归用例。
