# Agent Harness 与运行时

Harness 把模型变成可以持续执行任务的系统。它组装上下文、调用模型、执行工具、回填结果，并在预算耗尽或任务完成时停止。

## 复习范围

| 模块 | 要讲清的内容 |
|---|---|
| Agent Loop | input → context → LLM → tool → observation → next turn |
| 状态模型 | message、turn、run、session、checkpoint 的关系 |
| 事件模型 | start、delta、tool call、tool result、error、end |
| 终止条件 | final answer、最大轮数、token/时间/成本、安全熔断 |
| 并发控制 | 只读工具并行，写操作串行，状态快照隔离 |
| 恢复 | append-only 日志、checkpoint、未完成调用的处理 |

## 高频问题

1. 一次 Agent 请求从用户输入到最终回答经过哪些步骤？
2. `tool_call` 和 `tool_result` 如何重新进入上下文？
3. Agent Loop 如何判断继续或停止？
4. 用户消息在工具执行期间到达，运行时怎么处理？
5. 热更新工具或 Prompt 时，如何避免在途请求漂移？
6. 进程崩溃后，哪些状态可以恢复，哪些不能？

## 容易讲错的地方

- API 通常无状态，客户端要维护并重发历史。
- 模型决定想做什么，运行时决定是否允许和如何执行。
- 超时不代表工具没有产生副作用。
- checkpoint 保存可序列化状态，不保存任意运行时对象。
- 观测 hook 不应改变执行结果，控制 hook 可以。

## 项目证据

准备一张事件时序图，并从 Trace 中找一条真实失败路径。说明首错发生在哪个 turn，运行时如何终止或恢复。
