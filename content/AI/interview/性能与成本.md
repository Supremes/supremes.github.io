# Agent 性能与成本

Agent 总延迟由多轮模型调用和工具执行累积。先判断是轮数过多，还是单轮过慢，再进入不同的排查路径。

## 复习范围

| 层面 | 指标 |
|---|---|
| 模型 | TTFT、prefill、decode、input/output token |
| 缓存 | cache read、cache creation、稳定前缀 |
| Agent Loop | turn 数、回退、重复工具调用 |
| 工具 | 开始时间、耗时、并发度、失败率 |
| 任务 | 端到端 p50/p95/p99、cost per success |
| 容量 | RPM、TPM、队列、背压和限流 |

## 高频问题

1. Agent 比竞品慢，第一步怎么拆？
2. TTFT 高和总生成时间长分别说明什么？
3. 为什么上下文越长，成本可能非线性增长？
4. 哪些工具可以并行，哪些必须串行？
5. Prompt Cache 为什么会失效？
6. 如何权衡成功率提升与 token、延迟增加？

## 排查顺序

1. 对齐模型、Prompt、工具、缓存和任务样本。
2. 比较 turn 数和单 turn 耗时。
3. 单 turn 内拆排队、prefill、decode 和工具。
4. 找重复调用、无效回退和大体积工具结果。
5. 用成功任务成本做最终比较。

## 失败模式

- 只看平均延迟，忽略 p95。
- 只记录工具耗时，不记录开始时间，看不出串并行。
- A 组缓存命中，B 组冷启动。
- 用更便宜的模型，但失败重试导致总成本更高。
- 压缩上下文时丢失关键约束。

## 项目证据

准备一条慢 Trace 的瀑布图。指出主要耗时在轮数、prefill、decode 还是工具，并给出优化前后数据。
