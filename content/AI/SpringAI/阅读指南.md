TLDR：不要按模块目录从头啃 Spring AI；从一条最小调用链入手，再横向拆解扩展机制。推荐顺序： `ChatClient → ChatModel → Advisor → Tool Calling → RAG → MCP → 自动配置与可观测性`

 1. 先建立全局模型：Spring AI 本质是把不同模型厂商统一成 Spring 风格抽象，重点理解  Prompt / Message / ChatModel / ChatResponse / EmbeddingModel 。
 2. 跟一条最小调用链：从  ChatClient.create(chatModel).prompt().user(...).call().content()  开始，逐层跟到  DefaultChatClient 、Advisor 链、 ChatModel.call() ，最后进入具体厂商实现。
 3. 研究扩展机制：重点看 Advisor 如何拦截请求与响应，以及 Chat Memory、日志、重试、Guardrail 等横切能力如何接入。
 4. 研究模型能力映射：对照 OpenAI、Anthropic、Ollama 等实现，观察统一接口如何处理流式响应、结构化输出、多模态和 Tool Calling。
 5. 研究 RAG 数据链路：按  Document → Reader/Transformer → EmbeddingModel → VectorStore → Retriever/Advisor → Prompt  跟读，先理解数据流，不要先陷入某个向量数据库。
 6. 研究 Tool Calling 与 MCP：关注工具定义、参数 Schema、模型发起调用、Java 方法执行、结果回填，以及 MCP 如何把工具和资源标准化。
 7. 研究 Spring Boot 集成：阅读 starter、 AutoConfiguration 、 @ConditionalOn...  和配置属性，理解一个模型 Bean 怎样被自动装配出来。
 8. 最后看工程化能力：包括 Observation/Micrometer、重试与限流、Token Usage、评估、测试替身及生产监控。
